# Project Scope

**Project:** Mortgage Intelligence Platform (Fannie Mae–style secondary mortgage capstone)
**Owner:** Capstone team (see [team-charter.md](./team-charter.md))
**Status:** Baseline (Milestone 1)

---

## Problem statement

Secondary mortgage market participants buy, hold, and service large portfolios of residential loans originated by other lenders. Their operational risk sits in the gap between data and decisions: servicing events are scattered across systems, payment histories are hard to reconcile, delinquency is often spotted late, and the documents that support each loan (income verification, appraisals, disclosures) live in separate stores with weak links to the loan record.

The Mortgage Intelligence Platform brings these concerns into one auditable system. It gives servicing agents a single view of a loan's status and history, gives risk analysts portfolio-level delinquency metrics computed from the same source of truth, ties documents to loans with secure storage, and adds an AI assistant that answers policy questions grounded in approved guidance. The platform is built with enterprise practices (version control, reviewed changes, security zones, CI/CD, observability) so the result looks like something a regulated institution could operate.

## Objectives

The objectives are measurable against the 12-week program:

1. **Data foundation by Week 2.** A versioned PostgreSQL schema covering borrowers, mortgages, loans, payments, servicing history, delinquency, and documents, with reproducible migrations and synthetic seed data.
2. **Portfolio analytics by Week 3.** A Python service that reports portfolio size, outstanding balance, delinquency rate, borrower risk, and payment trends, matching SQL aggregates exactly.
3. **Servicing APIs by Week 5.** Java/Spring Boot services that expose mortgage creation, payment posting, servicing history, and delinquency status via `/api/v1` REST endpoints.
4. **Event-driven lifecycle by Week 6.** Lifecycle events (`MortgageCreated`, `PaymentReceived`, `PaymentMissed`, `LoanDelinquent`) published and consumed through messaging with dead-letter handling.
5. **Secured and production-ready by Week 12.** JWT-based role access, a STRIDE threat model, an automated CI/CD pipeline with security scans, Terraform-managed AWS infrastructure, and end-to-end tests that cover the full lifecycle.

## In-scope functionality

Over the program, the team implements these lifecycle areas:

- **Borrower onboarding.** Create and retrieve borrower records with business IDs (`BOR-###`) and validated contact data.
- **Mortgage management.** Create mortgages (`MTG-####`) linked to borrowers, track original amount, outstanding balance, and status (`PENDING`, `ACTIVE`, `DELINQUENT`, `CLOSED`).
- **Underwriting support.** Record loan terms (`LOAN-####`) and underwriting decisions (`PENDING`, `APPROVED`, `DECLINED`); give underwriters policy guidance through the AI assistant.
- **Servicing.** Keep a chronological servicing history per mortgage (onboarding, payments, status changes, contact attempts).
- **Payments.** Post payments with idempotency keys, keep scheduled and posted payment records, and update outstanding balance.
- **Delinquency.** Apply the canonical 30-day rule, keep a current delinquency snapshot (days past due, severity), and emit delinquency events.
- **Analytics.** Portfolio summary, delinquency report, borrower risk summary, and monthly payment trends.
- **Document management.** Upload loan documents to S3 with metadata in PostgreSQL, keyed by mortgage.
- **Security.** Role-based access for six personas, audit-friendly logs with correlation IDs, threat model, and security testing.
- **AI assistant.** Retrieval-augmented Q&A over mortgage policy documents with cited sources.
- **Operations.** Containerized services, CI/CD with quality and security gates, Terraform infrastructure, dashboards, alerts, and runbooks.

## Out of scope

- Real securitization, MBS pooling, or trading desk functionality.
- Integration with real Fannie Mae, Freddie Mac, MERS, credit bureau, or payment network systems.
- Real borrower data of any kind. All data is synthetic.
- Borrower-facing mobile apps or app store releases.
- Production deployment to a regulated environment, and formal regulatory compliance certification (e.g. SOC 2, GLBA audit).
- Full loan origination (LOS) workflows such as rate locks, credit pulls, and closing.

## Assumptions

- All data is synthetic, generated by the team, using `example.test` email domains and `555` phone numbers.
- Development happens locally and in AWS sandbox accounts provided by the program; no production AWS accounts are used.
- PostgreSQL is the system of record for transactional data; S3 holds document binaries.
- Environments are named `dev`, `test`, and `prod`; `prod` is simulated for the capstone.
- Each team member has a workstation with Git, Java 17, Python 3.11+, Docker, and PostgreSQL client tools (see [engineering-standards.md](./engineering-standards.md)).
- An identity provider is represented by service-issued JWTs in M6; an external IdP is a placeholder.

## Non-functional requirements (initial)

| Area | Initial requirement |
| --- | --- |
| **Security** | TLS for all traffic crossing a trust boundary; role-based authorization on every API from M6; no secrets or PII in Git; secrets supplied through environment variables or a secrets manager. |
| **Privacy** | Synthetic data only; logs never contain passwords, tokens, full SSNs, or full account numbers. |
| **Auditability** | Every request carries an `X-Correlation-Id` that appears in logs and events; servicing changes are recorded in `servicing_history`. |
| **Availability** | Target 99.5% for API tier in the simulated `prod` environment; health endpoints on every service. |
| **Performance** | Single-mortgage reads under 300 ms p95 on seed-scale data; portfolio analytics under 2 s on seed data. |
| **Data integrity** | Foreign keys on all relationships; money stored as `NUMERIC(15,2)`; payment and delinquency updates in one transaction. |
| **Maintainability** | Consistent conventions per [engineering standards](./engineering-standards.md); every change reviewed via pull request. |
| **Observability** | Structured JSON logs; metrics and dashboards by M9. |
